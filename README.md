# 논문 리더

다운받은 논문 PDF를 **책처럼** 읽는 로컬 프로그램.

세분화된 목차, 화면에 맞춘 페이지 넘김, 영어 논문 번역 토글, Kindle 스타일 UI.
서버에 올리지 않고 각자 자기 컴퓨터에서 실행한다.

## 무엇을 하나

- **책처럼 읽는다.** PDF의 2단 컬럼을 풀어서 한 줄로 흘리고, 화면에 맞춰 페이지를 나눈다.
  글자를 키우면 페이지가 다시 흐른다.
- **번역을 토글한다.** 원문 ↔ 한글을 `t` 한 번으로 오간다. 나란히 놓지 않는다.
- **인용이 각주가 된다.** 본문의 `[12]`가 그 페이지 아래에 실린다. 누르면 전문이 뜬다.
- **수식이 수식으로 보인다.** PDF에서 뭉개진 LaTeX를 복원해 KaTeX로 그린다.
- **그림·표는 한 쪽을 통째로 쓴다.**
- **읽던 자리를 기억한다.** 북마크·하이라이트·메모도 함께.
- **전체 텍스트 검색** — 원문·번역 양쪽에서 찾는다.

## 어떻게 동작하나

```
[PDF]  →  전처리 (논문당 1회)  →  [중간 JSON]  →  뷰어 (localhost)
          Docling 파싱                            페이지네이션 · 목차
          DeepL 번역                              번역 토글 · 각주 · KaTeX
          CrossRef 메타데이터                     하이라이트 · 검색
```

무거운 처리(파싱·번역)는 전처리에서 **한 번만** 한다. 뷰어는 가공된 JSON만 읽어서
가볍게 표시한다. 논문을 한 번 넣으면 다음부턴 즉시 열린다.

전처리와 뷰어를 잇는 계약이 [중간 JSON 스키마](schema/SCHEMA.md)다. 양쪽 다 여기에 맞춰
독립적으로 개발한다.

## 설치

Python 3.12 필요.

```bash
git clone <이 저장소>
cd paper-reader

python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS / Linux

pip install -r requirements.txt
```

첫 설치는 무겁다 — Docling이 PyTorch를 끌고 온다.

### DeepL 키 (번역을 쓸 때만)

**각자 자기 키를 써야 한다.** [DeepL API](https://www.deepl.com/pro-api)에서 무료로
발급받는다. 저장소에는 키가 들어 있지 않고, `.env`는 git이 무시하므로 올라가지 않는다.

```bash
cp .env.example .env
# .env 를 열어 DEEPL_API_KEY 를 채운다 (형식: xxxxxxxx-...-xxxxxxxxxxxx:fx)
```

키가 없어도 파싱과 읽기는 그대로 동작한다. 번역 토글만 비활성화된다.

무료 한도는 계정마다 다르다(실측한 계정은 월 100만 자였다). 논문 한 편에 3~4만 자쯤
쓰므로 한 달에 20~30편 정도 된다. 같은 문장은 캐시되어 두 번 번역하지 않는다.

## 사용법

### 1. 논문 넣기

```bash
python -m pipeline data/input/paper.pdf
```

| 옵션 | 뜻 |
|------|-----|
| `--no-translate` | 번역 없이 원문만 (DeepL 한도를 아낀다) |
| `--offline` | 네트워크를 쓰지 않는다 (CrossRef 조회 생략) |
| `--force` | 캐시를 무시하고 다시 파싱 |
| `--lang KO` | 번역 언어 (기본 KO) |

첫 실행은 Docling 모델을 받느라 수 분 걸린다. 이후 같은 논문은 캐시에서 즉시 열린다.

### 2. 읽기

```bash
python -m viewer          # http://localhost:5000
```

| 조작 | |
|------|---|
| 페이지 넘김 | `←` `→` · `Space` · 화면 좌우 끝 클릭 |
| 처음 / 끝 | `Home` `End` |
| 번역 토글 | `t` |
| 북마크 | `b` |
| 찾기 | `Ctrl+F` |
| 하이라이트 | 글자를 끌면 메뉴가 뜬다 (메모도 가능) |
| 각주 | 페이지 하단에 자동. 본문 `[12]`를 누르면 전문 |
| 글자 크기 | 하단 `A−` `A+` |

## 알려진 환경 문제 (Windows)

- **설치 직후 첫 실행이 한 번 실패할 수 있다.** Smart App Control이 갓 받은 패키지를
  잠시 차단하기 때문이다 (`애플리케이션 제어 정책에서 이 파일을 차단했습니다`).
  설치가 깨진 게 아니므로 다시 실행하면 된다.
- **한국어 Windows의 cp949 문제는 프로그램이 알아서 처리한다.** UTF-8 모드로 스스로
  재실행하므로 `PYTHONUTF8=1`을 붙일 필요가 없다.

## 알려진 한계

정직하게 적어둔다.

- **하이라이트는 그은 언어에만 남는다.** 글자 위치로 잡는데 원문과 번역문은 글자 수가
  달라서 옮길 방법이 없다. 원문에서 그은 것은 원문에서만 보인다.
- **고유명사가 번역될 수 있다.** DeepL이 데이터셋 이름 `FireMan`을 "소방관"으로 옮긴
  사례가 있다. 수식과 인용은 태그로 보호하지만 고유명사는 아직 아니다.
- **번역 문체가 섞인다.** 문단마다 독립적으로 번역되어 "~한다"와 "~합니다"가 오간다.
- **수식이 가끔 깨진다.** Docling의 수식 모델이 `\text{an}`을 `\an`으로 뱉는 등
  실수를 한다. 깨진 수식은 빨갛게 보이고 나머지 페이지는 정상이다.
- **각주 칸은 높이가 고정이다.** 각주가 없는 페이지도 그만큼 아래가 비어 보인다.
  (페이지마다 높이를 바꾸면 본문이 다시 흐르고 → 인용이 다른 페이지로 가고 → 각주가
  또 바뀌는 순환에 빠진다.)
- **스캔본 PDF는 확인하지 않았다.** 텍스트 레이어가 없으면 OCR을 자동으로 켜지만
  실제로 검증한 적은 없다.

## 폴더 구조

| 폴더 | 역할 |
|------|------|
| `schema/` | 중간 JSON 스키마 — 전처리와 뷰어의 계약. [왜 이렇게 정했는지](schema/SCHEMA.md) |
| `pipeline/` | 전처리: Docling 파싱 → 번역 → JSON 생성. [Docling 실측 결과](pipeline/DOCLING_FINDINGS.md) |
| `viewer/` | Flask 로컬 웹앱 (Kindle 스타일 뷰어) |
| `data/` | 논문 PDF와 처리 결과 (git에 올리지 않음) |

## 기술 스택

| 레이어 | 선택 |
|--------|------|
| PDF 파싱 | [Docling](https://github.com/DS4SD/docling) — 2단 컬럼·표·읽기순서 자동 정리 |
| 번역 | [DeepL API Free](https://www.deepl.com/pro-api) — 교체 가능하게 추상화 |
| 웹 서버 | Flask (127.0.0.1 전용) |
| 저장 | SQLite — 읽기 상태·북마크·하이라이트 |
| 수식 | KaTeX (CDN) |
| 메타데이터 | CrossRef API |

## 설계 메모

두 가지만 알아두면 나머지가 따라온다.

**페이지는 저장하지 않는다.** 중간 JSON에 페이지 개념이 없다. 페이지 나누기는 뷰어가
화면 크기와 글자 크기를 보고 매번 계산한다. 그래서 읽던 위치·북마크·하이라이트는
전부 **블록 id** 기준이다. (실측: 같은 논문이 글자 15px에서 34쪽, 26px에서 60쪽.
페이지 번호로 저장했으면 글자 크기를 바꾸는 순간 전부 어긋난다.)

**인용과 수식은 태그로 보호한다.** 본문에 `<c id="ref12"/>` `<m id="m1"/>` 같은 빈 XML
태그를 심어두고, DeepL의 `ignore_tags`로 번역에서 지킨다. LaTeX를 그냥 던지면 깨진다.

자세한 계획은 [paper_reader_plan.md](paper_reader_plan.md) 참고.
