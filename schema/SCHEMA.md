# 중간 JSON 스키마 — 설계 결정

`paper.schema.json` 이 정식 정의이고, `example.json` 이 그 스키마를 만족하는 예시다.
이 문서는 **왜 그렇게 정했는지**를 남긴다. 나중에 "이건 왜 이렇지" 싶을 때 여기부터 본다.

## 1. 페이지 개념이 없다

`blocks` 는 그냥 순서 있는 배열이고, 어디서 페이지가 끊기는지는 JSON에 없다.

페이지 나누기는 **뷰어가 실행 시점에** 화면 크기·글자 크기를 보고 매번 계산한다.
글자 크기를 바꾸면 페이지 수가 달라져야 하므로, 페이지 번호를 파일에 못 박을 수 없다.

여기서 따라 나오는 결론:

- **읽던 위치·북마크·하이라이트는 페이지 번호가 아니라 블록 id(`b0001`) 기준으로 저장한다.**
- 진행률 바는 "몇 쪽 중 몇 쪽"이 아니라 전체 블록 대비 현재 블록 위치로 계산한다.
- 따라서 블록 id 는 재처리해도 안 흔들려야 한다. 논문을 다시 파싱했더니 id 가 밀려서
  북마크가 엉뚱한 데를 가리키면 안 된다.

## 2. 인라인 태그 — 인용과 수식을 번역에서 지키는 방법

문단 텍스트 안의 인용과 수식은 두 종류의 빈 XML 태그로 표시한다.

| 태그 | 뜻 | 가리키는 곳 |
|------|-----|------------|
| `<c id="ref12"/>` | 인용 표시 | `references` 의 해당 항목 |
| `<m id="m1"/>` | 인라인 수식 | 같은 블록의 `inline_math` |

즉 원문은 이렇게 저장된다:

```
Recurrent models <c id="ref12"/> factor computation, where <m id="m1"/> is a function of ...
```

**왜 이렇게 하나:** DeepL에 LaTeX를 그냥 던지면 깨진다. 대신 DeepL의 XML 처리 기능
(`tag_handling="xml"`, `ignore_tags=["c", "m"]`)을 쓰면 이 태그들을 번역하지 않고
어순에 맞게 옮겨만 준다. 수식과 인용 번호가 원형 그대로 살아남는다.

**규칙:**
- `text_translated` 는 `text_original` 과 **같은 태그 집합**을 반드시 가진다. 위치는 어순 따라 바뀌어도 되지만, 개수와 id 는 같아야 한다. (파이프라인에서 검증할 것)
- 태그 밖의 `&`, `<`, `>` 는 이스케이프한다. 텍스트가 XML-safe 여야 태그 처리가 동작한다.
- 뷰어는 렌더링할 때 `<m>` 은 KaTeX로, `<c>` 는 각주 링크로 바꿔 넣는다.

## 3. 수식은 두 종류

- **인라인 수식** — 문단 안에 박힌 것. 블록의 `inline_math` 에 LaTeX로 담고 본문엔 `<m>` 태그만.
- **display 수식** — 독립된 줄에 놓인 것. `equation` 타입의 **별도 블록**.

display 수식을 별도 블록으로 뺀 이유는 페이지네이션 때문이다. 뷰어가 "이 수식은 통째로
다음 페이지로 넘긴다" 같은 판단을 하려면 수식이 독립 단위여야 한다.

`latex` 에는 `$$` 구분자를 넣지 않는다. 뷰어가 KaTeX에 넘길 때 알아서 붙인다.

## 4. 번역 안 된 상태도 유효하다

`text_translated` 류는 전부 nullable 이다. 번역 없이 파싱만 돌린 결과도 정상적인 파일이고,
뷰어는 그걸 열 수 있어야 한다 (번역 토글이 비활성으로 뜰 뿐).

DeepL 키가 없거나 무료 한도(월 50만 자)를 넘겨도 파이프라인이 통째로 죽지 않게 하려는 것이다.

## 4-2. 그림은 `image_paths` — 배열인 이유

한 그림에 이미지가 여러 개일 수 있다. (a)(b) 로 나뉜 복합 그림이 캡션 하나를 공유한다.

실측(FireMan 논문 Fig. 6): Docling 아이템 순서가 `PictureItem, PictureItem, caption` 이었다.
두 이미지가 "Fig. 6: Semi-automatic annotation with thermal and RGB image annotation"
캡션 하나를 나눠 갖는다.

처음엔 `image_path` 단수로 두었다가 실제 논문을 보고 배열로 바꿨다. 뷰어는 한 블록의
이미지들을 한 쪽에 나란히 배치한다 — 원래 논문에서도 나란히 있던 것들이다.

## 5. 그림·표는 기본이 `full_page: true`

계획대로 그림·표는 한 쪽 통째로 배치한다. 다만 플래그로 둔 이유는, 작은 그림까지 한 쪽을
다 먹으면 오히려 읽기 나쁠 수 있어서다. 나중에 크기 보고 파이프라인이 판단해 끌 여지를 남겼다.

표는 Docling이 뽑아주는 HTML을 그대로 담는다. 표 번역은 셀 단위로 해야 해서 Phase 1에서
후순위로 미룰 수 있다 (`table_html_translated` 를 null로 두면 됨).

## 6. 아직 안 정한 것

- **목차 "세분화"의 구체적 의미** — 지금 스키마는 Docling이 준 섹션 구조를 그대로 담을 수
  있게만 되어 있다. LLM으로 더 잘게 쪼갤지는 실제 논문을 파싱해 본 뒤 판단한다.
  쪼개기로 하면 `toc` 중첩만 깊어지고 스키마 자체는 안 바뀐다.
- **블록 id 안정성 보장 방법** — 지금은 등장 순서대로 `b0001`. 재처리 시 앞에 블록이
  하나 끼면 뒤가 전부 밀린다. 실제로 문제가 되면 내용 해시 기반 id 를 고려한다.
